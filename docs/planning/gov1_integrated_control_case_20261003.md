# GOV-1 integrated control case — implementation state

Date: 2026-10-03

GOV-1 is one cross-repository engineering-control plane over the existing ITIR/SensibLaw authorities. It does not create a second semantic compiler, review authority, acquisition authority, access authority, or standards-certification subsystem.

Canonical trace:

```text
User story
-> requirement
-> risk
-> control
-> implementation
-> evidence
-> residual / CAPA
-> release state
```

## Critical laws

```text
implemented != validated
compile_checked != runtime_observed
passing control != certified
selected != preferred
first rendered != best
hidden != absent
filtered != dominated
blocked != dominated
executable != Pareto
frontier != authorized
potential reopening != actual reopening
information-processing metadata != Matter visibility authority
governance state != INV priority
```

## Hard gates that remain separate

GOV-1 does not pay these unrelated programme obligations:

1. REL-1C independently sourced Wikidata↔prose / biomedical / multilingual-Wikipedia corpus acceptance.
2. Live INV PostgreSQL acquisition queue/update receipt over a real persisted REL residual.
3. Physical Dioxus desktop/GPU acceptance.
4. Production performance/economy closure.
5. Standards certification; GOV-1 makes no such claim.

## Promotion rule

Repository code may advance independently through service-change state and evidence state. A repository may be `implemented + source_written`, `implemented + compile_checked`, or `verified + fixture_checked`; no state is inferred from the other axis.

A suite release case must preserve the per-repository evidence rather than replacing it with a manually authored aggregate status.
